Харків – 2026

1. Мета заняття:
     Ознайомитися з основними рекомендаціями щодо написання якісного коду мовою Go (Golang), організації структури коду та підвищення його читабельності, зрозумілості й зручності подальшої підтримки.
2. Завдання
     Обрати мову програмування, дослідити основні рекомендації щодо написання якісного програмного коду, продемонструвати їх застосування на прикладах, обґрунтувати важливість кожної рекомендації та пояснити наслідки її недотримання.
3. Опис виконаної роботи
     Go (Golang) – це статично типізована та компільована мова програмування загального призначення, розроблена компанією Google. Вона була створена з метою поєднання високої продуктивності системних мов (таких як C++) із простотою читання та написання коду, характерною для динамічних мов. Однією з головних переваг Go є потужні та прості вбудовані інструменти для конкурентного програмування, що дозволяють ефективно працювати з багатоядерними процесорами та складними мережевими системами.
     Офіційний відкритий реліз мови відбувся у 2009 році, а стабільна версія 1.0 вийшла у 2012-му. Завдяки своїй надійності, масштабованості та швидкодії, Go швидко набрала популярність і стала одним із головних стандартів у сфері хмарних обчислень та мікросервісної архітектури. Це призвело до її широкого впровадження у розробку високонавантажених бекенд-систем, інфраструктурних інструментів (таких як Docker) та розподілених додатків.
3.1  Правила іменування
3.1.1 Рекомендація: використовуйте імена, що чітко передають наміри.
     Опис: ім’я змінної, функції або класу має давати вичерпні відповіді на запитання: чому ця сутність існує, що вона робить і як використовується. Якщо ім'я вимагає додаткових коментарів, воно не передає намірів розробника. У мові Go для публічних функцій та структур використовується PascalCase, а для приватних та локальних змінних – camelCase.
     Приклад: 
      // Поганий приклад (використовуються беззмістовні імена)
      var d int
      func GetThem(theList [][]int) [][]int { /* ... */ return nil }
      
      // Гарний приклад
      var elapsedTimeInDays int
      func GetFlaggedCells(gameBoard [][]int) [][]int { /* ... */ return nil }
     
     Пояснення кожної рекомендації:
- Чому важливо: змістовні імена значно спрощують розуміння та модифікацію коду, оскільки контекст і бізнес-логіка стають очевидними з самих назв змінних та функцій.
-  Наслідки недотримання: використання таких імен, як d або theList, змушує інших розробників витрачати час на детальне вивчення контексту (що саме знаходиться у списку, і що за час мається на увазі), що підвищує ризик внесення помилок.
- Вплив на підтримку: код, який читається як звичайна мова і не приховує зміст за абстрактними абревіатурами, має значно менший когнітивний наклад при підтримці.
     3.2 Правила написання функцій
     3.2.1. Рекомендація: функція повинна виконувати лише одну операцію.
     Опис: функції мають бути максимально компактними і виконувати тільки одну дію. Якщо всередині функції можна виділити секції (наприклад, ініціалізація, обчислення, запис), або якщо команди знаходяться на різних рівнях абстракції, таку функцію необхідно розбити на декілька менших.
     Приклад: 
      // Поганий приклад (функція виконує кілька операцій на різних рівнях абстракції)
      func ProcessOrder(order Order) {
          if order.Quantity <= 0 {
              return
          }
          total := float64(order.Quantity) * 15.5
          db.Save(order.ID, total)
      }
      
      // Гарний приклад 
      func ProcessOrder(order Order) {
          if !isValid(order) {
              return
          }
          saveToDatabase(order.ID, calculateTotal(order))
      }

     Пояснення кожної рекомендації:
- Чому важливо: дотримання правила однієї операції дозволяє зробити функцію прозорою, самодокументованою та ізольованою, що є ключовим для написання модульних тестів.
-  Наслідки недотримання: великі функції-моноліти, де змішуються різні рівні абстракції, швидко стають заплутаними, їх важко читати, тестувати та модифікувати.
- Вплив на підтримку: розбиття на дрібні функції дозволяє читати програму згори донизу, що радикально прискорює пошук помилок та внесення змін новими членами команди.

     3.3 Правила аргументів-прапорців
     3.3.1. Рекомендація: уникайте використання аргументів-прапорців у сигнатурах функцій
     Опис: аргументи-прапорці є потворними, і передача логічного значення функції – це жахлива звичка. Вона негайно ускладнює сигнатуру методу і гучно проголошує, що функція виконує більше однієї операції: одну дію, якщо прапорець істинний, і зовсім іншу – якщо хибний. Замість передачі логічного аргументу, таку функцію слід розбити на дві незалежні.
     Приклад: 
      // Поганий приклад (Використовується прапорець, виклик виглядає як render(true))
      func Render(pageData PageData, isSuite bool) {
          if isSuite {
              // логіка підготовки для набору тестів
          } else {
              // логіка підготовки для одного тесту
          }
      }
      
      // Гарний приклад
      func RenderForSuite(pageData PageData) {
          // логіка підготовки для набору тестів
      }
      
      func RenderForSingleTest(pageData PageData) {
          // логіка підготовки для одного тесту
      }

     Пояснення кожної рекомендації:
- Чому важливо: розбиття функції на дві окремі робить код набагато зрозумілішим і позбавляє виклики від неоднозначності. Виклик RenderForSuite() є абсолютно прозорим і не потребує занурення в реалізацію, щоб зрозуміти, що саме відбувається.
-  Наслідки недотримання: виклики на кшталт Render(pageData, true) збивають читача з пантелику. Програмісту щоразу доводиться переходити до визначення функції, щоб з’ясувати, за що відповідає передане значення true або false.
- Вплив на підтримку: усунення прапорців зменшує цикломатичну складність коду (менше розгалужень if / else). Це робить код значно простішим для модульного тестування та безпечнішим при подальшій підтримці, оскільки зміни в одній гілці логіки ніяк не зачеплять іншу.

4. Висновки
     У ході роботи було досліджено основні рекомендації щодо написання якісного програмного коду мовою Go (Golang). Розглянуто принципи використання змістовних імен змінних і функцій, організації функцій за принципом виконання однієї операції та уникнення аргументів-прапорців.
     Для кожної рекомендації наведено приклади програмного коду, обґрунтовано її важливість та проаналізовано наслідки недотримання. Встановлено, що застосування розглянутих рекомендацій сприяє підвищенню читабельності коду, спрощує його тестування, модифікацію та подальшу підтримку.
