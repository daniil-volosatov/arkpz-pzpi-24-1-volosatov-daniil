2. Завдання
     Обрати 3 методи рефакторингу коду програмного забезпечення за книгою Роберта Мартіна «Чистий код», пояснити їх призначення, показати приклади програмного коду та обґрунтувати вплив кожного прийому.
3. Опис виконаної роботи
     Рефакторинг – це зміна внутрішньої структури програмного коду з метою покращення його якості. На відміну від додавання нової функціональності, рефакторинг спрямований на зменшення складності, усунення дублювання та покращення організації вже реалізованої логіки.
     Для демонстрації обрано мову Go (Golang) – компільовану, статично типізовану мову програмування. Її функції, методи, зрозуміла система типів дозволяють наочно показати структурні перетворення та перевірити результат.
3.1  Виділення функції
3.1.1 Суть прийому: коли функція містить окремий логічний крок, його можна винести в допоміжну функцію зі змістовною назвою. Це відповідає рекомендаціям Мартіна щодо невеликих функцій, одного рівня абстракції.
     Початковий код: 
     
      func Total(qty int, price float64) float64 {
          subtotal := float64(qty) * price
          return subtotal * 1.2
      }
     
     Код після рефакторингу: 
     
      func Subtotal(qty int, price float64) float64 {
          return float64(qty) * price
      }
      
      func Total(qty int, price float64) float64 {
          return Subtotal(qty, price) * 1.2
      }

     Пояснення змін: обчислення підсумку перенесено у Subtotal, а Total тепер виражає послідовність обчислення: спочатку базова вартість, потім множник 1.2. Для тих самих аргументів повертається те саме число. Нову функцію можна тестувати окремо.
     
     3.2 Усунення дублювання (DRY)
     3.2.1. Суть прийому: дублювання правил у кількох місцях коду створює ризик неузгоджених змін і порушує принцип DRY (Don’t Repeat Yourself). Рефакторинг полягає у винесенні спільної логіки або формули в окрему функцію.
     Початковий код: 
     
      func AdultPrice(p float64) float64 {
          return p – p * 0.1
      }
      
      func StudentPrice(p float64) float64 {
          return p – p * 0.2
      }
      
     Код після рефакторингу: 
      
      func WithDiscount(p, rate float64) float64 {
          return p – p * rate
      }
      
      func AdultPrice(p float64) float64 {
          return WithDiscount(p, 0.1)
      }
      
      func StudentPrice(p float64) float64 {
          return WithDiscount(p, 0.2)
      }

     Пояснення змін: спільну формулу винесено у функцію WithDiscount, тоді як початкові функції зберегли свої назви та коефіцієнти (0.1 і 0.2). Це дозволяє позбутися дублювання й змінювати розрахунок централізовано.
     
     3.3 Принцип розділення команд і запитів
     3.3.1. Суть прийому: принцип розділення команд і запитів (Command–Query Separation) вимагає, щоб операція або змінювала стан системи, або повертала дані без жодних модифікацій. Рефакторинг розмежовує ці обов’язки на окремі функції, усуваючи неочевидні побічні ефекти під час звичайного читання даних.
     Опис: аргументи-прапорці є потворними, і передача логічного значення функції – це жахлива звичка. Вона негайно ускладнює сигнатуру методу і гучно проголошує, що функція виконує більше однієї операції: одну дію, якщо прапорець істинний, і зовсім іншу – якщо хибний. Замість передачі логічного аргументу, таку функцію слід розбити на дві незалежні.
     Початковий код: 
     
      func (c *Counter) Next() int {
          c.value++
          return c.value
      }

     Код після рефакторингу: 

      type Counter struct { value int }
      func (c *Counter) Increment() {
          c.value++
      }
      
      func (c *Counter) Value() int {
          return c.value
      }
     Пояснення змін: початковий метод Next одночасно збільшував лічильник і повертав результат. Після перетворення Increment лише змінює значення, а Value лише читає його. Щоб отримати результат колишнього виклику Next, треба послідовно викликати Increment та Value. Окрема перевірка необхідна, щоб усі місця виклику зберегли потрібний порядок операцій.
4. Висновки
     У ході роботи було розглянуто три прийоми покращення структури програмного коду: виділення функції, усунення дублювання (DRY) та розділення команд і запитів (Command–Query Separation). Для кожного прийому наведено приклади мовою Go до і після структурних змін.
     Встановлено, що виділення функції підвищує зрозумілість окремих обчислень, усунення дублювання полегшує супровід спільних правил, а розділення команд і запитів допомагає контролювати побічні ефекти..
